# What the 0.13 baseline taught us

The baseline: 12 tasks, one run each, Claude Haiku and Sonnet in five
conditions (tachyon bare, with the guide, with the tools, with both; the
same task in Rust), tachyon 0.13.0. Tables:
[0.13-baseline.md](0.13-baseline.md), raw results
[0.13-baseline.json](0.13-baseline.json). Qwen3-Coder (local) runs are
still in progress and will be added.

## The results

- **Both models solve almost everything, in tachyon as in Rust.** Each
  solved 59 of 60 runs. This suite has hit its ceiling for hosted models,
  so the signal is in the cost, not in the success rate.
- **Tachyon costs about 2.7–3× Rust's input tokens to write from
  scratch.**

  | model, condition | median input tokens | median time |
  |---|---|---|
  | Sonnet, tachyon with both | 146k | 39 s |
  | Sonnet, Rust | 55k | 33 s |
  | Haiku, tachyon with both | 529k | 100 s |
  | Haiku, Rust | 167k | 51 s |

  The cost is learning the language: the write-from-spec tasks (01–06,
  12) carry it.
- **On existing code, tachyon costs about what Rust does.** On the fix
  and extend tasks (07–09, 11), Sonnet with no guide spent 51–197k
  tokens, against 73–123k in Rust. Reading a program teaches the
  language.
- **The refactor task is the one where the tools win.** On
  10-refactor-rename, Sonnet with the tools took 103k tokens, and with
  both 172k tokens in 27 s. In Rust it took 160k tokens and 33 s.
  Renames and moves are what `refactor` was built for.
- **The guide is the biggest lever.** For both models, guide ≈ both <
  bare < tools-only in tokens. Given the tools table without the guide,
  the agents explore:
  - Haiku made 134 `query` calls over 12 small tasks, a median of 36
    tool calls per run against 18 with the guide.
  - On programs of a few hundred lines, reading a file costs less than
    querying it piece by piece.
- **Both failures had the same cause, in the bare condition.** Both
  models failed 06-intervals there.
  - **Sonnet** could not find how to read stdin. It guessed about 30
    names (`read_line` first) and got "undefined variable" with no hint
    each time, then gave up.
  - **Haiku** gave up after the harness refused one compound shell
    command.
- **Writing a string constant is a common first error.** Agents wrote
  `const ALPHA: [u8] = "..."` and got an error that did not say to use
  `static`.
- **Several runs lost 10+ minutes to a hung program.** A bare `./prog`
  waited on stdin inside the agent's shell; such runs show up as
  800–1000 s outliers in wall time.
- **About 1 in 10 Claude tool calls was refused.** The permission check
  refuses shell lines it cannot verify in advance (`$?`, heredocs,
  loops, `&&` chains), in every condition including Rust.

## What changed because of it

**In 0.14:**
- **std:**
  - `read_line`, `read_stdin`, a `Scanner`, `parse_int` and
    `split_whitespace`: reading input with no `unsafe`;
  - in-place map and vector updates (`get_or_insert(k, 0)[0] += 1`,
    `Vec::swap`, `insert`, `remove`);
  - an introsort, 2–3× faster.
- **Diagnostics:**
  - did-you-mean across the program and std;
  - an unknown name that std has gets the exact `use std::{name};`
    line, and an unknown name with no close match points to
    `tachyonc guide std`;
  - string constants;
  - privacy errors with a `pub` fix, reported together with the other
    errors;
  - integer literals typed from the other branch.
- **Tools on a user program:**
  - `./main.tach` is the default root;
  - `undo` and `query diff` work without git;
  - locals can be renamed;
  - `refactor variant --arm-in`;
  - edits add the imports their new text needs.
- **The harness:** the prompt says to rephrase a refused command rather
  than stop, and to run programs with `< input`.

**Planned:**
- **The guide:** the tools topic and the core guide's tools table say
  when the tools pay off (renames, moves, signature changes, errors
  across files) and when reading a small file is cheaper.
- **The suite:** harder tasks, so that the hosted models' success rate
  says something:
  - larger multi-module programs;
  - porting a C program;
  - a compiler-like pass over an AST;
  - perf tasks with tighter limits;
  - several reps per cell.

Evals are not rerun every release; the next run comes after the harder
tasks are in.
