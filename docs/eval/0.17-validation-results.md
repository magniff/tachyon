## Read this first: drift

The same `guide` condition on three hard tasks, with only the compiler
(0.17), harness and day changed, costs **Sonnet x1.42 input tokens, +3
turns** against the 0.16 baseline (1 of 3 tasks inside the baseline's
range; Haiku x0.78). So a comparison of a new cell with a 0.16 cell on the
hard tasks carries a shift of that size by itself. The verdicts below rest
on the same-compiler controls where they exist (A-control on 01-12, drift
on 13/16/17, C-plain for the compiler tasks) and use the 0.16 cells only
where nothing else exists (D's `both --check-hook`: Dctl ran no runs, the

## Anomalies, fixes, and what was done with each

1. **Dry-run harness bug (fixed, rerun).** The dry step failed
   `both+hook+test` on its first try: synthetic hook events used the fixed
   session id `dry-run`, so the hook state left by an earlier dry run at
   the same paths made the delta hook say "1 error (1 as before)" without
   listing it. Real sessions have unique ids. lib/runner.py now gives each
   dry run its own id; rerun 12/12 ok.
2. **Check-hook bug, the tool under test (in v0.16.0's hook too; fixed
   after the round).** `tachyonc edit replace|insert NAME < new.tach` made
   check-after-edit.py take the stdin file as the program root (the
   redirect and its path are among the parsed words): the snippet was
   checked alone. It fired in 4 C and 5 D compiler runs (10 records); one
   reported errors to the agent (C Haiku 21 rep1: 9 bogus "undefined
   variable" errors and the guide hint), adding 1 distinct name error to
   that cell (name/API 0.50 -> 0.42 per run without it). Not fixed
   mid-round, since the hooks are the condition under test. Fix:
   `operands()` drops redirections; 3 new cases in
   test-check-after-edit.py (67 pass).
3. **Load-induced grading timeouts (regraded, not rerun).** Four
   16-perf-tight failures (A Haiku rep3, A Sonnet rep2, drift Sonnet rep2,
   tools Sonnet rep8) were test timeouts graded while four compiler tasks
   built alongside; `run.py regrade --only-failed` on a quiet machine: all
   four pass 12/12. The three 17-debug-crash failures stay (wrong output).
   Next round: no program grading alongside compiler builds.
4. **SIGKILL of target/tachyonc (harness; fixed after the round).** In D
   Haiku 22 rep2, `target/tachyonc` died with 137 on every call after
   eval-build.sh's `cp` overwrote the signed binary in place (macOS kills a
   binary overwritten in place). The agent diagnosed it and worked around it
   (74 turns, 761 s). Its patch touches only compiler/src and the grading
   rebuilds in a fresh copy, so the success stands. The run is kept and
   flagged: it is the high outlier of D-C Haiku 22, and the medians are
   robust to it. It is 1 of 120 compiler transcripts. lib/eval-build.sh now
   removes the old binary before copying.
5. **The stray `pkill -9 -f "prog$"` at 2026-10-15T20:53:22Z (22:53:22
   local).** Every run live within +-2 min was checked: the program stream
   had finished at 22:43:32, so only the D compiler cell was running.
   Eight runs (D Haiku 21 rep1, 21 rep2, 23 rep1, 24 rep1; D Sonnet 21, 22,
   23, 24 rep3) show no kill and passed every grading step: unaffected,
   kept. D Haiku 22 rep2 started 37 s after the pkill and its 137s are item
   4 (4 minutes later, on every call, from a build-script copy): not the
   pkill, kept. The 20:53:22 local reading was also checked (drift Haiku
   17 rep2: "137" only inside program output): unaffected, kept. No run
   was excluded or rerun.
6. **Dctl ran nothing.** The 0.16-hook baseline already had every (13-18,
   rep 1-3) cell, so `--skip-existing-in` skipped all. The `both+hook`
   control is therefore 0.16's check hook on the 0.16 compiler, not 0.17's
   delta hook (the plan expected the latter for missing cells only).
7. **Error counts in hook cells are not comparable across rounds.** 0.17
   runs count the errors the hooks showed (hook-output.jsonl), 0.16 runs
   could not. D's `errors` row (0.11 -> 2.28) is that, not a regression.
   The item 5 table uses cells without hooks.
8. **The plan's "20-60 min per compiler run" is the whole round.**
   Compiler runs took 0.6-13 min, like 0.16's.
