# The 0.17 validation round: the rerun matrix against the 0.16 baseline

[docs/research/applying-to-tachyon.md](../../../docs/research/applying-to-tachyon.md)
§3 ranks ten changes for 0.17 and §4 gives the matrix of focused reruns
that decides them. This round runs **only the deciding cells**, against
the clean 0.16 round of 2026-10-15 as the baseline: same tasks, same
models (Sonnet, Haiku), same 3 reps for the controls, which are not run
again where the baseline has them (`run.py run --skip-existing-in`).
One command: `sh tests/agent-eval/plans/0.17-validation.sh` (`STEP=...`
for one step; resumable like every round).

## The baseline

`BASE` (default `.claude/briefs/evalruns/0.16` of the main checkout):

| directory | what | used as |
|---|---|---|
| `0.16-programs-claude-sonnet` | 18 tasks x bare, both, rust (+ guide on 13-18) x 3 | controls `guide` (13-18), `both`, `rust`, `bare` |
| `0.16-programs-claude-haiku` | the same for Haiku (the round was still filling it) | the same; missing cells are run (A-control) |
| `0.16-hook-claude-*` | 18 tasks x `both --check-hook` x 3 | the `both+hook` control of row D |
| `0.16-compiler-claude-*` | 4 compiler tasks x compiler-tools, compiler-plain x 3 | the controls of row C |

Not the baseline: `0.16-compiler-mktemp-*` (the first compiler pass, in
which no agent could run tests/run.sh: the sandbox and mktemp; kept apart)
and `0.16-dry`. The program runs of the baseline were regraded with the
round's grading fixes (eval-run16: 18-api-refactor's and 13-port-c's
check.sh, 10-refactor-rename's `type Item`, the retried timeout).

Three things differ from the baseline in every new cell and are measured
rather than held fixed:

- **the compiler** under test for the program tasks is the 0.17
  candidate (`TACHYONC`; it has the short core guide, `tachyonc guide
  --full`, and later `tachyonc test`). The `drift` step runs the `guide`
  control on three hard tasks with it: if its cost is inside the
  baseline cell's range, the compiler swap is not what moves the other
  cells;
- **the permission allowlist** is wider (lib/claude_backend.py: every
  command the 0.16 agents chained, `./*`, Edit rules for the sandbox's
  temp directory, loops). The baseline's denials (0.6 per Sonnet `both`
  run, 2.7 per compiler-tools run; heredocs, `$VAR`, chains, writes to
  /tmp/claude-UID) are compared with the new runs' in every table, by
  cause (`anatomy.denials`); the self-check's probes record which forms
  are still refused (2026-10-15, Haiku: only a `for` loop of 14 forms).
  This replaces matrix row F: `bypassPermissions` is not used;
- **the harness** records more (anatomy, hook output); the baseline's
  anatomy is computed from its transcripts (`run.py analyze`), without the
  hooks' output, which 0.16 did not keep: error counts of hook runs are
  comparable only for the errors the agent's own builds and checks showed.

## Decision rules (the research plan's thresholds)

`run.py compare` prints, per model and pair of conditions, per task: the
successes, the median input tokens with the baseline cell's IQR (its
range with 3 reps; a new median inside it is marked `~`: noise), the
ratio, turns and cost; then the median ratio over the tasks with the
exact Wilcoxon signed-rank p (paired by task), and the anatomy's means
(verify calls, guide calls, `query context` calls, denials, errors and
the name/API class, repair calls per error, edit failures, hook blocks
and escapes).

| item | comparison | confirmed if | refuted if |
|---|---|---|---|
| 1 core guide | A: `guide-core` vs `guide` (baseline 13-18 + A-control 01-12) and vs `rust` | input tokens -30% on 01-12, turns within 1, success equal | turns +3, or a task loses a rep `guide` passes |
| 1 its form | G: `rust-pairs` vs `guide-core` | fewer Rust-habit errors (the Rust habits table) at equal turns | more habits or turns |
| 2 tiered AGENTS.md | C: `compiler-tools-core` vs `compiler-tools` and `compiler-plain` (baseline) | tokens fall on 23 and 24; 22's tools/plain stays under 0.4 | 22 loses its advantage |
| 7 `query context` | C, tools: `query context` calls per run | used in a third of the runs, those runs not costlier | under 0.5 calls per run: drop the row |
| 3 `tachyonc test` | D: `both+hook+test` vs `both+hook` (0.16-hook) vs `both` | verify calls and denials -33% (Haiku), turns down | turns unchanged |
| 5 diagnostics | E vs A: errors by class | name/API errors per run halved, repair calls per error under 1.2 | unchanged |
| allowlist | every cell: denials per run by cause | denials near 0 (a loop is the one form left) | the same causes as 0.16 |

A difference smaller than the control cell's spread is noise, whatever
its direction (0.16's 17-debug-crash: 129k bare, 368k both, 201k guide
for Sonnet).

## Labels: what each new condition is

- `guide-core`: prompts/guide-core.md (the intro) + `tachyonc guide` of
  `TACHYONC` (the ~1.7k-token example-first core); `guide` in a 0.17
  round inlines `tachyonc guide --full`, the 0.16 core as 0.17 keeps it
  (4,618 words against 0.16's 4,569: the same text with 0.17's
  corrections), so the baseline's `guide` and the new one are comparable.
- `compiler-tools-core`: the task's base (v0.16.0) with its AGENTS.md
  "Read source through the compiler" section replaced by this checkout's
  (0.17's tiered section). `compiler-tools` in the baseline is 0.16's
  full table: the task's base decides, not this checkout, so a rerun of
  `compiler-tools` on v0.16.0 is still the 0.16 text. The tiered section
  links docs/query.md#every-command-at-a-glance-for-agents, which v0.16.0's
  docs do not have (a dead link in the workspace; the table itself is
  complete).
- `TOOLS_TACHYONC` (default: unset, the starter's tools): with it, the
  compiler-tools conditions' `target/tools/tachyonc` is that binary
  (0.17's query context, `edit std::NAME`, ...) on the same 0.16 tasks;
  set it for C once items 4 and 6 have landed, and say so in the report.
- The hooks are this checkout's tools/agent-hooks (0.17's when merged),
  run under lib/hook-tee.py so that what they told the agent is kept.

## Not yet in the round: a second compiler feature task

The matrix asks for two more compiler tasks; the cheap one is a feature
with a diagnostic: on v0.16.0, `use std::io::stdin;` and `use
std::collections::HashMap;` say `no 'io' in module 'std'` with no help.
Task 25 (to write): the error gets `help: tachyon's std is one module;
items are imported directly` and, when the last segment names a std item,
`try: use std::{HashMap};`; a hidden case per form; grade.sh checks the
help and the try line on three inputs; the reference solution touches the
use-path resolution in front/check. It was left out of this round to keep
it on the baseline's four tasks; it costs one task-authoring day.
