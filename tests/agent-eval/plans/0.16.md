# The 0.16 agent-eval round

To run once v0.16.0 is tagged and its compiler built. Nothing here has
been run against hosted models yet, except one check of the hooks (below).

## In one command

From the repository root (a checkout that has this runner, i.e. after the
eval-016 branch is merged), with `target/tachyonc` built from v0.16.0
(`bootstrap/bootstrap.sh` at the tag, so the bootstrap cache also holds
v0.15.0, which builds the compiler tasks' base):

```sh
sh tests/agent-eval/plans/0.16.sh
```

It stops at the first problem and resumes where it stopped when run
again (finished runs are skipped). `STEP=check|dry|programs|hook|compiler|report`
runs one step; `MODELS`, `REPS`, `JOBS`, `CJOBS`, `TACHYONC`, `OUT` are
in the script's header.

## The steps

1. **Validate on 0.16.0** (about 15 min):
   `run.py check-tasks --set all --tachyonc target/tachyonc`. The 18
   program tasks: both reference solutions pass and the starters fail
   with the 0.16 compiler. The compiler tasks: `starter.patch` and
   `solution.patch` apply to v0.16.0, the starter builds and fails the
   grading, the reference passes it. When a patch no longer applies
   (0.16 moves the compiler's source to `?`, derive and interpolation),
   regenerate it as the task's README says, then rerun this step.
2. **Dry run** (about 5 min, no model): every compiler task in both
   conditions: the workspace, the prompt and settings, and the hooks
   fired on synthetic events. The script checks that in compiler-tools
   the check hook reports an error a Write added and the query hook
   blocks a `grep` of compiler source, and that compiler-plain has no
   hooks.
3. **Program tasks**: the 18 tasks of `tasks/` in `bare`, `both` and
   `rust`, 3 reps each, both models side by side (`--jobs 6` each).
   `bare` and `rust` are the two ends; `both` is what a user of tachyon
   gets. The 0.13 baseline had 12 tasks, 1 rep and 5 conditions; `guide`
   and `tools` alone are left out on 01-12 (0.13: guide ≈ both, tools
   alone costs most), which leaves room for the reps. **On the hard tasks
   13-18, `guide` is run too** (3 reps, both models, after their bare,
   both and rust runs): `both` against `bare` mixes the guide and the
   tools; `both` against `guide` isolates what the tools add on the tasks
   where they should matter.
4. **The check hook**: the same 18 tasks in `both` with `--check-hook`
   (0.15), 3 reps, in its own results directory: against step 3's `both`
   it shows what the hook saves (the 0.14 tool-gaps study counted 124
   eval calls running `check` straight after an edit).
5. **Compiler tasks**: the tasks of `ctasks/` in `compiler-tools` and
   `compiler-plain`, 3 reps, both models (`--jobs 2` each: every run
   builds the compiler and runs tests on all cores).
6. **Reports**: `docs/eval/0.16.md` (steps 3 and 5; the compiler tasks
   in "Compiler tasks: tools against plain") and
   `docs/eval/0.16-check-hook.md` (step 4), each with its `.json`.
   Then write `docs/eval/0.16-findings.md` as for 0.13, and add the
   rows to docs/eval/README.md's table.

fixpoint, the task's test filters, same-output for the refactor).

## The sandbox and mktemp (found in the round)

macOS `mktemp` without a template (or with `-t`) ignores `$TMPDIR` and
uses the per-user temp directory, which the agent's sandbox cannot
write. `compiler/std/embed.sh` and `compiler/guide/embed.sh` call it so
and `tests/run.sh` runs `embed.sh -c` before any case, so in the first
pass of step 5 every compiler-task agent found `tests/run.sh` failing
(48 of 48 runs) and could not regenerate std's embedded copy (task 24).
The runner now puts a `mktemp` shim in every agent's bin directory (a
template in `$TMPDIR`); step 5 was run again with it, and the first pass
is kept apart (`0.16-compiler-mktemp-*`, not in the report).
`run.py regrade` grades finished compiler runs again from their
`changes.patch`, and a suite that stops before its cases is reported
with its first lines.

## Grading fixes (found in the round, runs re-graded)

Every affected run was graded again from what it kept (`run.py regrade`:
a program run's `workspace.tar.gz`, a compiler run's `changes.patch`),
without running the agent again; result.json keeps the old grading as
`regraded_from`.

- 18-api-refactor's check.sh read `enum LoadError` up to the first `}`,
  so a Rust enum with struct-like variants lost its later variants and
  correct Rust runs failed; it now counts braces (also `struct Pos`).
- 13-port-c's check.sh rebuilt the program from `cp $files` into one
  directory, so an agent's `scratch/main.tach` replaced `main.tach`; it
  now copies the workspace with its directories.
- 10-refactor-rename's check.sh: `type Item =` and `Iterator<Item = ...>`
  (the iterator protocol) no longer count as the old name.
- A hidden test that times out runs once more: four 16-perf-tight runs
  timed out at 2.5 s with programs that take 0.2-0.6 s alone, the
  grading sharing the machine with 8 agents.
- A Claude session that ends twice (a background task finishing after the
  answer starts another turn) is counted whole: turns, tokens and denials
  summed over its `result` events (2 runs were undercounted).

## What to look at

- **Program tasks, tools on the hard tasks**: 13-18 in `both` against
  `guide` (the tools' own share) and against `bare`.
- **Compiler tasks, tools against plain** (the question of this round):
  success, input tokens, turns and wall time per model and task; the
  refactor task is where the tools should win most (0.13: the tools won
  only on 10-refactor-rename); the fix task is where reading by name may
  cost more than grep. The hooks: blocks, `# no-query` escapes (their
  reasons are in result.json's `query_hook` and each run's
  `agent-tools.jsonl`: feed them to the next tool-gaps study), check-hook
  checks with errors.
- **Program tasks**: the tachyon/Rust gap in input tokens on the harder
  tasks 13-18, with 3 reps (0.13: 2.7-3x on writing, about 1x on fixing);
  success rates (0.13 hit the ceiling on 01-12).
- **The check hook**: `both` with and without it: tool calls, turns,
  `tachyonc:check` calls, `final_check` errors left.
