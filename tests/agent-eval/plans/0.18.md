# The 0.18 round: value semantics, contracts, and what the agents think

Run right after tachyon 0.18.0 ships, from a 0.18 checkout holding this
runner (merge eval-018 first). One command:
`sh tests/agent-eval/plans/0.18.sh` (`STEP=...` for one step; resumable
like every round). Two questions:

1. **How do agents fare** with 0.17's value semantics (moves, drops,
   `&`/`&mut`, views) and 0.18's contracts and tests: cost against Rust,
   turns, success, and the compile errors they hit by family (`own.*`,
   `contract.*`, `test.*`, `distinct.*`), against the 0.17 rounds.
2. **What do they think of the language**: every run ends with a
   debrief (`+debrief`, below), the Rust runs about Rust as the baseline.

216 runs, about $18 (Sonnet ~$12, Haiku ~$6), ~143M input tokens
(mostly cache reads), ~4M output; the debriefs about $2 of it (`STEP=estimate`
prints this from the 0.17 iterations' medians; Haiku's 15-multi-module is
the largest single item). Hosted Claude models only (Sonnet, Haiku): no
ollama. Permissions are the allowlist (never `bypassPermissions`).

- **The condition** is the 0.17 iterations' adopted default,
  `guide-mini+readfirst` (docs/eval/0.17-iterations.md, closing summary:
  "adopt guide-mini+readfirst as the default for both models"), and its
  Rust twin. guide-mini and the core guide teach 0.17's style (`&mut`
  receivers, moves, drops; no `defer free`; `v[i]`, `v.sort()`), checked
  for this round.
- **Tasks**: iteration 1's seven (01, 03, 06 from a spec; 08, 10, 16, 17
  on existing code), the 0.17 rounds' comparison set, plus three where
  owned values move and drop most: 04 (a ledger of structs), 14 (an AST of
  nested enums), 15 (three modules passing owned state). The starters and
  solutions are 0.17 code (T7's migration; trait impls and parameters
  respelled by `fix --values` for this round), and `check-tasks` passes.
- **Reps**: 3 for Sonnet, 6 for Haiku: a prompt-level change on Haiku
  needs 6+ reps a cell to be read (iterations 5-7: every guide change lay
  inside the 3-rep spread).
- **Compiler tasks**: 21 and 23 are the two whose patches apply to the
  0.18 tree (checked on release-0.18 at 30118560: 23 passes; 21's
  solution passes its own filters, and the one failure, the toposort
  example, fails on that tree without it; 22's and 24's patches no longer
  apply). The `check` step checks them on `CBASE` again; if one fails
  there, drop it with `CTASKS=`.
- **Contracts and tests**: no task asks for them and the default guide
  does not name them, so `contract.*` and `test.*` errors will appear only
  where an agent finds the feature (`guide --find`) or std raises one; the
  families are counted anyway, and the debrief asks what confused them. A
  cell that names contracts and tests in the prompt is a decision for
  after this round (it would change the condition).

## The debrief (`+debrief`)

After the task's turn ends (pass or fail), the same session gets one more
message (prompts/debrief.md): what in the language confused or surprised
it, which diagnostics helped or misled (with the code if it remembers
it), the one change it would make to the syntax or semantics, and three
ratings out of 5: readability, ease of getting it correct, confidence the
program is right; at most 150 words, one labelled line each. `rust` runs
are asked about Rust, compiler runs about tachyon and its tools.

It does not touch the task's numbers (lib/debrief.py, lib/claude_backend.py):

- the prompt goes in on stdin (`--input-format stream-json`) instead of
  as the argument; the model sees the same first message. When the
  task's `result` event has come and the stream has been quiet 3 s, the
  debrief is sent as a second user message of the same session (cache
  warm: one request, mostly cache reads); a task that times out or dies
  is not asked;
- its events go to `debrief.jsonl`; every task metric (turns, tokens,
  cost, anatomy) comes from `transcript.jsonl` as before; its cost is the
  session's cumulative cost after it minus the task's
  (`result.json`: `debrief.cost_usd`, `.answer`, `.words`, `.tool_calls`);
- the workspace is snapshotted when the task's turn ends and put back
  after the debrief, before the final check and the grading;
- not with a Stop hook (`+test`, `+turn-end`: it would act on the
  debrief's turn), Claude only.

`run.py debrief RUNDIR... --md FILE` groups the answers: ratings per model
and condition (and confidence for passed against failed runs), each
field's themes by keyword (moves, references, drops, views, raw
pointers, allocators, text, std names, contracts, tests, distinct types,
lifetimes for Rust, helpful/misleading diagnostics; no model), quotes per
theme, the diagnostic codes the answers name, then every answer per task.

The smoke run (2026-10-16, Haiku, devtasks/00-hello-sum,
`guide-mini+readfirst+debrief`): the task passed (6/6, 15 turns,
$0.0078); the debrief answered in the form in 119 words, 0 tool calls,
$0.0008, 5.5 s; the workspace was restored; `run.py debrief` parsed the
three ratings (4/4/4) and its themes (the `.len` field against `.len()`).

## The comparison

`report` writes:

| file | what |
|---|---|
| `0.18-costx.md` | `run.py costx`: cost x Rust against 0.18's own Rust cells, tier-free cost x Rust, success, turns, peak context, requests over 100k; per task; errors per run by family |
| `0.18-costx-rust016.md` | the same against the 0.16 Rust cells, the 0.17 iterations' denominator, with 0.18's Rust as a cell (did Rust move: the model, the harness) |
| `0.18-vs-night017.md` | `run.py compare` against night-017's `guide-mini+readfirst` (iteration 3), paired per task |
| `0.18-vs-0.17v.md` | against the 0.17 validation's `guide-core` (0.17v-A) |
| `0.18-vs-rust.md` | tachyon against Rust in this round, paired |
| `0.18-compiler.md` | compiler tools against plain on 21, 23 |
| `0.18-results.md` | `run.py report`: every cell |
| `0.18-debrief.md` | `run.py debrief`: what the agents think |

Baselines (`BASE`, the main checkout's `.claude/briefs/evalruns/`):
`0.16/` (the `rust` cells), `0.17-validation/0.17v-A-*` (`guide-core`,
release-0.17's compiler), `iter/03-night017/` (`guide-mini+readfirst`,
night-017). Errors by family (`run.py costx`): `own` is 0.17's `own.*`
codes (in the Rust rows, Rust's borrow-checker errors: the like-for-like
friction of value semantics), then 0.18's `contract`, `test`,
`distinct`, then the anatomy's classes (name, type, match, syntax,
unsafe, alloc, effects, other), and the new families' codes one by one.

The harness lessons of the 0.17 iterations hold: a run's workspace root
is named by its whole `--out` path; a copy of the compiler that differs
from `--tachyonc` is replaced; every program run records the md5 of the
compiler it had (`result.json`'s `tachyonc_md5`), and `run.py binaudit
DIR... --expect TACHYONC` (the report's first command) checks it against
the binary in the run's own workspace root.

## Rerun: 0.18-polish (0.18.1)

The same round with the polished compiler and guide text (the 0.18
analysis, .claude/briefs/research/eval-0.18-analysis.md): tasks,
conditions, reps and models as above; what differs is the compiler
binary, the guide (`guide-mini`, `tachyonc guide std`'s first page),
the check hook (exact fixes applied) and the shell note's line on the
Edit tool and BSD `sed -i ''` (in the Rust condition too, so the
comparison stays fair). Copy the compiler first, so that a rebuild
during the round cannot change it (binaudit checks every run used it):

    mkdir -p target/eval && cp target/tachyonc target/eval/tachyonc-0.18-polish
    ROUND=0.18-polish CBASE=<the polish commit> \
        sh tests/agent-eval/plans/0.18.sh --compiler target/eval/tachyonc-0.18-polish

Results go to `results/0.18-polish-{P,C}-*`, the reports to
`docs/eval/0.18-polish-*.md`, among them `-costx-vs-0.18.md` (cost x
Rust of both rounds, the Rust cells side by side as a noise check) and
`-vs-0.18.md` (per task, paired with the first round's cells from
`PREV`, default the main checkout's .claude/briefs/evalruns/0.18);
`0.18-polish-manifest.txt` records the compiler's md5 and version, the
commit and the prompts' md5s.
